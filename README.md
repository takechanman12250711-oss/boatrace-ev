# boatrace-ev — ボートレース買い目分析システム

選手・モーター成績、直前情報、オッズ、過去レース結果から各艇の着順確率を出し、
**期待値（的中確率 × オッズ）が高い買い目**だけを提示する。

## 仕組み

```
過去データ(B/K LZH) ─┐
公式サイト(出走表/直前/オッズ/結果) ─┼→ SQLite → 特徴量 → 1着確率モデル → 3連単120通り/2連単30通りの確率
                                    │                                   ↓
                                    └──────── オッズ ──→ 市場確率と混合 → 期待値 → 買い目・金額 → docs/(GitHub Pages)
```

| 段階 | ファイル | 内容 |
|---|---|---|
| 取込 | `history.py` | 番組表(B)・競走成績(K)を一括取込。学習データの中心 |
| 取込 | `scrape.py` | 当日の出走表・直前情報（展示タイム/チルト/部品交換/スタート展示/気象）・オッズ・結果 |
| 特徴量 | `features.py` | 級別・勝率・モーター/ボート2連率・展示タイム差・進入コース・選手の近況(直近30走)・選手×コース1着率・場×コース1着率・風・波。過去成績系は必ず**そのレースより前**のデータだけで計算 |
| モデル | `model.py` | 勾配ブースティングで1着確率 → Plackett-Luce（2・3着の補正指数λを検証データで推定）で全組み合わせの確率 |
| 期待値 | `ev.py` | モデル確率とオッズ由来の市場確率を混合 → 期待値 ≥ しきい値・確率下限・オッズ上限で絞り、分数ケリーで金額 |
| 検証 | `backtest.py` | 過去期間で学習→未来期間で評価。しきい値は前半で調整、後半で評価（調整と評価を分ける） |

## 使い方

```bash
pip install -r requirements.txt
export PYTHONPATH=src

python -m boatev.cli history --from 20220101 --to 20261022   # 過去成績5年分（学習用）
python -m boatev.cli backfill-odds --from 20251001 --to 20261022 --max-minutes 300   # 過去オッズ（検証用・途中再開可）
python -m boatev.cli train
python -m boatev.cli backtest --test-from 20260801
python -m boatev.cli predict --within 20                      # 締切20分以内のレースを予想
python -m boatev.cli results
```

GitHub では Actions が自動実行する：
- `backfill-odds.yml`（手動・数回）過去オッズ補完
- `setup.yml`（手動・初回）過去データ取込 → 学習 → バックテスト
- `live.yml` 9〜22時に10分おき予想・結果反映 → `docs/data/` をコミット
- `nightly.yml` 毎晩、前日の確定データとオッズを蓄積。月曜に再学習

Settings → Pages で `main` ブランチの `/docs` を公開すると表示画面が見られる。

## 注意点

- 過去オッズは公式サイトの過去レースページから `backfill-odds` で補完する（1レース2アクセス、1日分約8分）。5年分は数百時間かかるので、まず直近1年分→足りなければ遡る。Actionsの `backfill-odds.yml` は約5時間で打ち切り、再実行で続きから取る。
- バックテストのオッズは確定オッズ。実際は締切前に買うので結果はやや楽観的。
- 学習時の進入コースは実際の進入、予想時はスタート展示の進入を使う（多くは一致）。
- 公式サイトのHTML構造が変わると `scrape.py` が値を取れなくなる。`python -m boatev.cli debug-page <URL>` で確認して直す。
- アクセス間隔は1.5秒（`BOATEV_INTERVAL`）。間隔を詰めないこと。
- 控除率が約25%あるため、長期でプラスにするのは簡単ではない。バックテストの**後半期間（holdout）の回収率**で判断する。
